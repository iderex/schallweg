# Code of conduct

## What is adopted

This project adopts the Contributor Covenant, version 2.1, as its code of
conduct. The text is at
`https://www.contributor-covenant.org/version/2/1/code_of_conduct/` and it is
what applies here.

It is adopted by reference at a fixed version rather than copied into this file,
and the reason is worth one sentence: a copy drifts against the thing it
describes and nothing in this repository would notice, so what a contributor is
held to would gradually become a document nobody had read against the original.
The cost is real and is not hidden. You have to follow a link to read what
applies to you, and a reader with no network in front of them cannot.

Version 2.1 is named rather than "the current version" on purpose. A later
version applies here when this file is changed to name it, and that change is a
pull request like any other.

## Where it applies

The issue tracker, pull requests, commit messages, and anywhere somebody is
plainly acting for this project. It is not a claim on what anybody does
elsewhere.

## How to report something

There is one private channel into this repository, and it is the security
advisory form:

`https://github.com/iderex/schallweg/security/advisories/new`

It reaches the maintainer and nobody else, and nothing sent through it becomes
public unless an advisory is published. Say plainly at the top that the report is
about conduct rather than a vulnerability.

That form was built for vulnerability reports and not for this, which is stated
here rather than glossed over. It is used anyway because it is the only private
route this repository has, and a code of conduct whose reporting route is a public
issue is not one anybody can use.

A report that does not need to be private can be a public issue.

## What happens to a report

It is read by the maintainer. You get an acknowledgement, and if none has arrived
within seven days the report has not been seen, in which case open a public issue
saying that a report is waiting, with none of its detail in it.

What follows is in the adopted text, which sets out the enforcement steps and
what each one means. This file adds nothing to them and does not soften them.

## When the maintainer is the problem

The route above goes to one person, so it is worth saying what to do when that
person is the subject of the report rather than the reader of it. There is no
second maintainer to send it to. What there is: the hosting service's own abuse
reporting, which does not go through this repository or anybody in it, and the
public issue tracker, which is slower and less comfortable and is nevertheless a
real route because the record is public and stays readable.

That is a thin answer and it is the true one. It gets better when there is more
than one maintainer, and not before.
